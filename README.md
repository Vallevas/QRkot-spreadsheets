# QRKot

Приложение для вымышленного благотворительного фонда поддержки котиков
**QRKot**. Фонд собирает пожертвования на всевозможные задачи, связанные
с помощью кошачьей популяции: на корм, медицинское обслуживание,
организацию приютов и другую помощь котам, кошкам и котятам.

## Как это работает

- В фонде может быть открыто несколько **целевых проектов** — каждый со
  своим названием, описанием и требуемой суммой. Когда нужная сумма
  собрана, проект автоматически закрывается.
- Пользователи делают **пожертвования** в фонд (не в конкретный проект)
  и могут сопроводить их комментарием.
- Каждое пожертвование автоматически инвестируется в самый «старый» из
  открытых проектов. Если сумма пожертвования больше, чем требуется
  текущему проекту, остаток переходит в следующий открытый проект.
  Если открытых проектов нет — деньги ждут появления нового.
- При создании нового проекта все свободные (неинвестированные)
  пожертвования автоматически вкладываются в него.
- Сделать пожертвование может только
  зарегистрированный и аутентифицированный пользователь.
  Управлять целевыми проектами (создание, редактирование, удаление) и
  просматривать полный список пожертвований может только суперюзер.
- При наличии токена Яндекс Диска (YANDEX_DISK_TOKEN в .env) суперпользователь
  может получить Excel-отчёт по закрытым целевым проектам — эндпоинт POST /yandex/.
  Проекты в отчёте отсортированы по скорости сбора средств (от самого быстрого
  к самому медленному). Файл сохраняется на Яндекс Диске в папке QRKot Reports,
  публикуется, и в ответе API возвращается
  публичная ссылка на него.

Вся логика распределения инкапсулирована в `app/services/investment.py`
и вызывается прямо из эндпоинтов создания проектов и пожертвований, в
рамках единой транзакции.

## Стек

- Python 3.12, FastAPI
- FastAPI Users — регистрация, аутентификация (JWT) и управление
  пользователями
- SQLAlchemy 2.0 (async) + aiosqlite
- Alembic — миграции БД
- Pydantic v2
- httpx — асинхронный HTTP-клиент для работы с API Яндекс Диска
- xlsxwriter — генерация Excel-отчётов

## Модели

**User** (таблица `user`)

| Поле              | Описание                        |
| ----------------- | ------------------------------- |
| `id`              | первичный ключ                  |
| `email`           | email пользователя (уникальный) |
| `hashed_password` | хеш пароля                      |
| `is_active`       | активен ли пользователь         |
| `is_superuser`    | является ли суперюзером         |
| `is_verified`     | подтверждён ли email            |

**CharityProject** (таблица `charityproject`)

| Поле              | Описание                            |
| ----------------- | ----------------------------------- |
| `id`              | первичный ключ                      |
| `name`            | уникальное название, 5–100 символов |
| `description`     | описание, не короче 10 символов     |
| `full_amount`     | требуемая сумма                     |
| `invested_amount` | собранная сумма                     |
| `fully_invested`  | закрыт ли проект                    |
| `create_date`     | дата создания                       |
| `close_date`      | дата закрытия                       |

**Donation** (таблица `donation`)

| Поле              | Описание                                     |
| ----------------- | -------------------------------------------- |
| `id`              | первичный ключ                               |
| `user_id`         | автор пожертвования (внешний ключ на `user`) |
| `comment`         | комментарий (необязательно)                  |
| `full_amount`     | сумма пожертвования                          |
| `invested_amount` | распределённая по проектам сумма             |
| `fully_invested`  | распределена ли вся сумма                    |
| `create_date`     | дата пожертвования                           |
| `close_date`      | дата полного распределения                   |

## Права доступа

| Действие                                              | Аноним | Пользователь | Суперюзер |
| ----------------------------------------------------- | :----: | :----------: | :-------: |

| Просмотр списка целевых проектов                      |   ✅   |      ✅      |    ✅     |

| Просмотр всех пожертвований                           |   ❌   |      ❌      |    ✅     |

## Установка и запуск

Клонируйте репозиторий:

```bash
git clone https://github.com/Vallevas/QRkot-spreadsheets
cd QRkot-spreadsheets
cp .env.example .env
```

В файле `.env` необходимо указать ваш OAuth-токен Яндекс Диска для работы интеграции. Также можно указать `SECRET` (секрет для подписи JWT-токенов)
и данные первого суперюзера (`FIRST_SUPERUSER_EMAIL`,
`FIRST_SUPERUSER_PASSWORD`) — этот пользователь будет создан автоматически
при первом запуске приложения, если ещё не существует.

Создайте и активируйте виртуальное окружение:

- Windows:

```bash
python -m venv venv
venv\Scripts\activate
```

- macOS / Linux:

```bash
python3 -m venv venv
source venv/bin/activate
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

Выполните миграции и запустите приложение:

```bash
alembic upgrade head
uvicorn app.main:app --reload
```

По умолчанию используется `sqlite+aiosqlite:///./fastapi.db`.

Документация будет доступна по адресу `http://127.0.0.1:8000/docs`.

## Примеры запросов к API

### Регистрация пользователя

```bash
curl -X POST http://127.0.0.1:8000/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "cat_lover@example.com",
    "password": "meow12345"
  }'
```

Ответ:

```json
{
  "id": 1,
  "email": "cat_lover@example.com",
  "is_active": true,
  "is_superuser": false,
  "is_verified": false
}
```

### Вход в систему (получение JWT-токена)

```bash
curl -X POST http://127.0.0.1:8000/auth/jwt/login \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "username=cat_lover@example.com&password=meow12345"
```

Ответ:

```json
{
  "access_token": "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...",
  "token_type": "bearer"
}
```

Полученный `access_token` нужно передавать в заголовке `Authorization`
для всех запросов, требующих аутентификации:

```bash
-H "Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9..."
```

### Получить данные текущего пользователя

```bash
curl http://127.0.0.1:8000/users/me \
  -H "Authorization: Bearer <ваш_access_token>"
```

Ответ:

```json
{
  "id": 1,
  "email": "cat_lover@example.com",
  "is_active": true,
  "is_superuser": false,
  "is_verified": false
}
```

### Отредактировать данные текущего пользователя

```bash
curl -X PATCH http://127.0.0.1:8000/users/me \
  -H "Authorization: Bearer <ваш_access_token>" \
  -H "Content-Type: application/json" \
  -d '{"email": "new_cat_lover@example.com"}'
```

### Создать целевой проект

Только для суперюзеров.

```bash
curl -X POST http://127.0.0.1:8000/charity_project/ \
  -H "Authorization: Bearer <access_token_суперюзера>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Новый вольер",
    "description": "Нужны деньги на строительство нового вольера для кошек",
    "full_amount": 50000
  }'
```

Ответ:

```json
{
  "name": "Новый вольер",
  "description": "Нужны деньги на строительство нового вольера для кошек",
  "full_amount": 50000,
  "id": 1,
  "invested_amount": 0,
  "fully_invested": false,
  "create_date": "2026-07-07T12:00:00"
}
```

### Получить список всех проектов

Доступно без аутентификации.

```bash
curl http://127.0.0.1:8000/charity_project/
```

### Отредактировать проект

Только для суперюзеров.

```bash
curl -X PATCH http://127.0.0.1:8000/charity_project/1 \
  -H "Authorization: Bearer <access_token_суперюзера>" \
  -H "Content-Type: application/json" \
  -d '{"full_amount": 70000}'
```

В ответ придет объект проекта с обновленными данными. Нельзя редактировать закрытый проект и нельзя установить `full_amount` меньше
уже внесённой суммы — в этих случаях вернётся ошибка `400`.

### Удалить проект

Только для суперюзеров.

```bash
curl -X DELETE http://127.0.0.1:8000/charity_project/1 \
  -H "Authorization: Bearer <access_token_суперюзера>"
```

В ответе придет объект удаленного проекта. Удалить можно только проект, в который ещё не поступали пожертвования.

### Сделать пожертвование

Только для зарегистрированных пользователей.

```bash
curl -X POST http://127.0.0.1:8000/donation/ \
  -H "Authorization: Bearer <ваш_access_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "full_amount": 3000,
    "comment": "На корм котятам"
  }'
```

Ответ (пользователю не показывается, как распределилось пожертвование):

```json
{
  "full_amount": 3000,
  "comment": "На корм котятам",
  "id": 1,
  "create_date": "2026-07-07T12:05:00"
}
```

Пожертвование автоматически инвестируется в самый старый открытый проект
в момент создания. Автор пожертвования определяется по токену
аутентификации, передавать `user_id` вручную нельзя.

### Получить список своих пожертвований

Только для зарегистрированных пользователей — возвращает пожертвования,
сделанные только пользователем, выполняющим запрос.

```bash
curl http://127.0.0.1:8000/donation/my \
  -H "Authorization: Bearer <ваш_access_token>"
```

Ответ:

```json
[
  {
    "full_amount": 3000,
    "comment": "На корм котятам",
    "id": 1,
    "create_date": "2026-07-07T12:05:00"
  }
]
```

### Получить список всех пожертвований

Только для суперюзеров.

```bash
curl http://127.0.0.1:8000/donation/ \
  -H "Authorization: Bearer <access_token_суперюзера>"
```

Здесь, в отличие от ответа при создании и от списка `/my`, видно
и распределение, и автора пожертвования:

```json
[
  {
    "full_amount": 3000,
    "comment": "На корм котятам",
    "id": 1,
    "create_date": "2026-07-07T12:05:00",
    "user_id": 1,
    "invested_amount": 3000,
    "fully_invested": true,
    "close_date": "2026-07-07T12:05:00"
  }
]
```

### Сформировать отчёт на Яндекс Диске

Только для суперюзеров.

```bash
curl -X POST http://127.0.0.1:8000/yandex/ \
  -H "Authorization: Bearer <access_token_суперюзера>"
```

Ответ — публичная ссылка на созданный Excel-файл:

```json
"https://disk.yandex.ru/i/xxxxxxxxxxxxxx"
```
